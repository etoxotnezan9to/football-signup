# Запись на футбол — VK Mini App

Замена записи плюсами в групповом чате: любой пользователь создаёт игру и становится её организатором, остальные видят список игр и записываются кнопкой «+» (до 5 мест на человека), список записавшихся обновляется у всех в реальном времени. Если мест не хватает, запись делится: например, при двух свободных местах «+3» даёт 2 места в составе и 1 в очереди. Оплату организатор отмечает вручную.

## Состав репозитория

| Каталог | Что внутри |
|---|---|
| `apps/api` | Fastify + WebSocket + SQLite (`node:sqlite`), проверка подписи параметров запуска VK |
| `apps/web` | React + VKUI, сквозные тесты Playwright (`e2e/`) |
| `packages/shared` | Типы, константы (`MAX_SEATS_PER_USER = 5`), валидация и **чистая логика очереди** |
| `docs` | Спецификация, контракт REST (`openapi.yaml`), протокол WebSocket, схема БД, `runbook.md` |
| `deploy` | Docker Compose, шаблон nginx, скрипты подготовки сервера, выкладки с откатом и бэкапа |

## Локальный запуск (без VK)

Нужны Node.js 22.18+ и pnpm.

Быстрее всего одной командой в тестовом режиме: API и веб-приложение запускаются вместе, база лежит в `apps/api/data/dev.db`.

```bash
pnpm install
pnpm dev:test
# откройте http://localhost:5173
```

Вручную по отдельности:

```bash
pnpm install
# API в режиме разработки: вход «Mock» разрешён только вне production
cd apps/api && AUTH_DEV_BYPASS=1 VK_APP_ID=54809461 DATABASE_FILE=./data/dev.db node src/server.ts
# в другом терминале: веб-приложение (проксирует /api и /ws на :3000)
pnpm --filter @football/web dev
```

В браузере приложение подставляет тестового пользователя; переключатель «Тестовый режим» вверху списка позволяет сменить пользователя и проверить очередь и обновления без второго аккаунта.

### Тестовые игроки

В тестовом режиме у организатора на странице игры есть блок «🧪 Тестовый режим»: можно сразу добавить до 50 тестовых игроков (по 1–5 мест каждому) и одной кнопкой убрать всех. Тестовые игроки — обычные записи в составе и очереди с фамилией «(тест)» и отрицательным id; уведомления VK им не отправляются. Режим включается сам при `AUTH_DEV_BYPASS=1`, а на сервере — строкой `TEST_MODE=1` в `.env` (см. `docs/runbook.md`). VK Tunnel не используется (отключён платформой), проверка внутри VK идёт на HTTPS-стенде, см. `docs/runbook.md`.

### Запуск под Windows

Команды выше написаны для bash: в PowerShell и cmd строка `AUTH_DEV_BYPASS=1 … node …` не работает. Порядок для PowerShell:

1. Установите Node.js 22.18 или новее (`winget install OpenJS.NodeJS.LTS`) и pnpm той версии, что указана в `packageManager` корневого `package.json`:
   ```powershell
   corepack enable   # если нет прав, запустите PowerShell от администратора
   pnpm --version
   ```
   Если `corepack` недоступен: `npm install -g pnpm@10.28.0`. **Не** выполняйте в каталоге проекта `npm install` или `npm install pnpm`: появятся `package-lock.json` и локальный pnpm в зависимостях, после чего `pnpm -r …` и e2e перестают запускаться. Если это уже случилось, верните `package.json` и `pnpm-lock.yaml` (`git checkout -- package.json pnpm-lock.yaml`), удалите `package-lock.json` и `node_modules` и снова выполните `pnpm install`.
2. Окончания строк: `.gitattributes` хранит `*.sh`, `deploy/` и `ci/` с LF при любом `core.autocrlf`. Если файлы получены до его появления, перевыгрузите их: `Remove-Item deploy/*.sh, ci/run.sh ; git checkout -- deploy ci`.
3. Установите зависимости из корня: `pnpm install`.
4. API. Удобнее всего через файл `apps/api/.env` (он в `.gitignore`), тогда переменные не зависят от оболочки:
   ```
   AUTH_DEV_BYPASS=1
   VK_APP_ID=54809461
   DATABASE_FILE=./data/dev.db
   ```
   и запуск с перезапуском при изменениях: `pnpm --filter @football/api dev`.
   Без файла, переменными текущей сессии PowerShell:
   ```powershell
   cd apps/api
   $env:AUTH_DEV_BYPASS = '1'; $env:VK_APP_ID = '54809461'; $env:DATABASE_FILE = './data/dev.db'
   node src/server.ts
   ```
   В cmd то же самое через `set AUTH_DEV_BYPASS=1` и так далее, по одной переменной на команду.
5. Во втором окне терминала: `pnpm --filter @football/web dev`, затем откройте http://localhost:5173. Если Windows спросит про доступ Node.js к сети, достаточно частных сетей.

Проверки из следующего раздела работают и под Windows. В Windows PowerShell 5.1 нет `&&`: запускайте команды по одной или через `;`. Скрипты из `deploy/` (bash) выполняются только на сервере. Копируйте их из рабочей копии с LF, иначе bash упадёт с `set: pipefail: invalid option name`.

## Проверки

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm --filter @football/web exec playwright install chromium   # один раз
pnpm --filter @football/web test:e2e                           # нужна предварительная сборка
# нагрузочный тест против запущенного API с AUTH_DEV_BYPASS=1
node apps/api/scripts/loadtest.ts --base http://127.0.0.1:3000 --users 200 --observers 10
```

CI (`.github/workflows/ci.yml`) запускает всё перечисленное, а также собирает Docker-образ API и проверяет `/api/health`. В ветке `develop-claude` CI сам обновляет `pnpm-lock.yaml`, если добавлены зависимости.

## Что реализовано

- Создание игры, список предстоящих игр, экран игры с составом и очередью, запись/изменение/отмена записи, лимит 5 мест.
- Обновление у всех пользователей через WebSocket; при потере соединения клиент переподключается, а затем перезапрашивает данные; запасной режим: опрос раз в 5 секунд.
- Организатор: редактирование и отмена игры, отметка оплаты по местам, удаление участника, «Скопировать список» в привычном текстовом виде.
- «Поделиться» (диалог VK) и ссылка на игру `https://vk.com/app<ID>#/game/<id>`.
- Ограничение частоты изменяющих запросов, проверка подписи VK и свежести параметров запуска.
- Личные уведомления VK (`docs/spec.md`, раздел 12): переход из очереди в состав, отмена и перенос игры, напоминание за сутки. Включаются, когда на сервере задан `VK_SERVICE_KEY`; в приложении есть приглашение разрешить уведомления.
- Нагрузочный тест `apps/api/scripts/loadtest.ts`: сотни одновременных записей на одну игру и наблюдатели по WebSocket; запускается в CI.

## Не реализовано

- Мониторинг ошибок (Sentry): нужно решение о подключении и DSN. Пока ошибки видны в логах контейнера (`docker compose logs`).
- Уведомления не проверялись на настоящем VK: для этого нужны сервисный ключ, прохождение модерации и пользователь, разрешивший уведомления. Логика покрыта тестами с подменой запросов к VK.
- Выкладка на сервер ни разу не запускалась на реальном сервере: `deploy/` написан и проверен только на уровне синтаксиса и пробного прогона плана на заглушках.
