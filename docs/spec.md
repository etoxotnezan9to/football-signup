# Спецификация: VK Mini App «Запись на футбол»

## 1. Цель

Заменить запись на игру плюсами в групповом чате ВКонтакте приложением: любой пользователь создаёт игру, видит список игр, записывается кнопкой «+» с выбором числа мест, а состав обновляется у всех в реальном времени.

## 2. Константы

| Имя | Значение | Смысл |
|---|---|---|
| `MAX_SEATS_PER_USER` | 5 | Максимум мест одного пользователя в одной игре суммарно (состав + очередь) |
| `MIN_CAPACITY` | 2 | Минимальная вместимость игры |
| `MAX_CAPACITY` | 60 | Максимальная вместимость игры |
| `MAX_FEE_RUB` | 100000 | Максимальный взнос, ₽ |
| `MAX_ACTIVE_GAMES_PER_ORGANIZER` | 10 | Активных (будущих) игр у одного организатора |
| `LIST_PAGE_SIZE` | 20 | Размер страницы списка игр |
| `LAUNCH_PARAMS_MAX_AGE_SEC` | 86400 | Допустимый возраст `vk_ts` в подписи |
| `WS_HEARTBEAT_SEC` | 25 | Период ping |
| `FINISH_GRACE_MIN` | 180 | Через сколько минут после начала игра считается завершённой |

Значения хранятся в `packages/shared` (`constants.ts`) и используются и сервером, и клиентом.

## 3. Сущности

**User**: `vkId` (число, уникален), `firstName`, `lastName`, `photoUrl` (может отсутствовать), `createdAt`.

**Game**:
- `id`, `organizerId` (User), `title` (1–80), `startsAt` (UTC, будущее на момент создания),
- `venue` (1–80), `address` (1–160), `format` (0–120, текст, например «6х6, 3 или 4 команды»),
- `feeRub` (0..`MAX_FEE_RUB`), `capacity` (`MIN_CAPACITY`..`MAX_CAPACITY`),
- `description` (0–1000), `paymentInfo` (0–300: реквизиты предоплаты текстом), `organizerContact` (0–120: ссылка VK или телефон для чека),
- `status`: `active` | `cancelled`, `createdAt`, `updatedAt`.
- Статус `finished` не хранится: игра считается завершённой, когда `now > startsAt + FINISH_GRACE_MIN` (вычисляется, поле `isFinished` в ответах).

**Signup**: `id`, `gameId`, `userId`, `seats` (1..`MAX_SEATS_PER_USER`), `paidSeats` (0..`seats`), `createdAt`, `updatedAt`. Одна запись на пару (игра, пользователь).

## 4. Правила очереди

1. Порядок: FIFO по `createdAt` записи (при равенстве — по `id`). Изменение числа мест не меняет `createdAt`, кроме случая из п. 6.
2. Состав вычисляется функцией `computeRoster(capacity, signups)`: записи идут по порядку; каждая получает `min(seats, свободно)` мест в составе, остаток уходит в очередь. Запись может быть разделена: часть мест в составе, часть в очереди (пример: свободно 2, «+3» → 2 в составе, 1 в очереди).
3. Продвижение очереди автоматическое: любое освобождение мест (отмена, уменьшение мест, удаление организатором, увеличение вместимости) пересчитывает состав; места получают первые по порядку.
4. Пользователь записывается через `PUT /games/:id/signup` с `seats` — желаемое **итоговое** число мест (1..5). Если записи нет, создаётся; если есть, число мест заменяется.
5. Уменьшение `seats`: освобождаются последние места записи (сначала очередь, потом состав). `createdAt` не меняется.
6. Увеличение `seats`: состав пересчитывается по правилу п. 2 с сохранением `createdAt`. Допущение: ранняя запись сохраняет приоритет, поэтому её увеличение может вытеснить в очередь более поздние записи, если свободных мест не хватает (см. пример 7).
7. Отмена записи: `DELETE /games/:id/signup`, запись удаляется.
8. Лимит: `seats` > `MAX_SEATS_PER_USER` — ошибка `SEATS_LIMIT_EXCEEDED`.
9. Организатор уменьшил `capacity`: записи не удаляются; состав пересчитывается, лишние места (с конца порядка) уходят в очередь. `capacity` нельзя установить меньше `MIN_CAPACITY`.
10. Игра отменена (`cancelled`) или завершена: записываться, менять и отменять запись нельзя (`GAME_NOT_ACTIVE`); составы остаются видимыми.
11. Оплата: `paidSeats` ставит только организатор (0..`seats`). Оплата вне приложения. Предупреждение в интерфейсе: «Предоплата не возвращается при отмене записи». Если `seats` уменьшилось ниже `paidSeats`, `paidSeats` обрезается до `seats`.
12. Организатор может записаться на свою игру как обычный участник.

## 5. Права доступа

| Действие | Кто |
|---|---|
| Создать игру | любой авторизованный |
| Просмотр списка и игры | любой авторизованный |
| Записаться, изменить, отменить свою запись | любой, пока игра active и не завершена |
| Редактировать игру, отменить игру | только организатор |
| Отметить оплату, удалить участника | только организатор |
| Список «мои игры» | сам пользователь |

## 6. Ошибки

Тело ошибки: `{ "error": { "code": "...", "message": "..." } }`.

| code | HTTP | Когда |
|---|---|---|
| `UNAUTHORIZED` | 401 | нет или неверная подпись VK |
| `FORBIDDEN` | 403 | не организатор |
| `NOT_FOUND` | 404 | нет игры или записи |
| `VALIDATION_ERROR` | 400 | неверные поля |
| `SEATS_LIMIT_EXCEEDED` | 422 | `seats` > 5 |
| `GAME_NOT_ACTIVE` | 409 | игра отменена или завершена |
| `ACTIVE_GAMES_LIMIT` | 422 | у организатора уже 10 активных игр |
| `STARTS_AT_IN_PAST` | 422 | `startsAt` не в будущем при создании |
| `RATE_LIMITED` | 429 | слишком частые запросы |

## 7. Сценарии и экраны

- **Список игр** (`/`): будущие активные игры по возрастанию `startsAt`; карточка: название, дата и время, площадка, взнос, «занято X/Y, в очереди Z», кнопка «+». Кнопка «Создать игру».
- **Экран игры** (`/game/:id`): все поля игры; состав и очередь (имена, число мест, метка «оплачено»); моя запись; кнопки «Записаться +N», «Изменить», «Отменить запись»; для организатора: «Редактировать», «Отменить игру», «Оплачено», «Удалить», «Скопировать список».
- **Форма игры** (`/create`, `/game/:id/edit`): поля из раздела 3 с валидацией.
- **Мои игры** (`/my`): созданные мной и те, куда я записан.
- **Запись «+»**: выбор числа мест (степпер 1..5), после подтверждения показывается результат («2 места в составе, 1 в очереди»).
- Все экраны слушают WebSocket и обновляются без перезагрузки.

## 8. Нефункциональные требования

- Изменения доходят до всех подписчиков не позднее чем за 2 секунды.
- Одновременные записи не превышают вместимость состава (транзакции `BEGIN IMMEDIATE`, один процесс API).
- Авторизация: подпись параметров запуска VK (HMAC-SHA256 с защищённым ключом приложения), заголовок `Authorization: VK <строка параметров запуска>`.
- Секреты только в переменных окружения.

## 9. Подпись VK

Из параметров запуска берутся только `vk_*`, сортируются по имени, формируется строка `k=v&...` (значения URL-кодируются), считается HMAC-SHA256 с защищённым ключом, результат в base64url без `=`, сравнивается с `sign` (сравнение за постоянное время). Параметр `vk_app_id` должен равняться `VK_APP_ID`. `vk_ts` не старше `LAUNCH_PARAMS_MAX_AGE_SEC`.

## 10. Текстовый список (кнопка «Скопировать список»)

Формат повторяет сообщение организатора:

```
{title}
📅 {дата и время}
📍 {venue}, {address}
💰 Взнос {feeRub}₽

Список:
1-6) Артём Миронов (6) ✅оплачено
7,8,9) Алексей Иванов (3) ✅оплачено 2
10) Николай Лисовалов

⚠ Мест нет! В очереди:
1) Григорий Захарьин
2,3) Филипп Коркунов (2)
```

Правила: нумерация сквозная по местам отдельно для состава и для очереди. Запись из одного места: `n) Имя`; из 2–3 мест: `a,b,c) Имя (k)`; из 4 и более: `a-b) Имя (k)`, где k — число мест в этой части. «✅оплачено» если `paidSeats` = `seats`, «✅оплачено N» если 0 < `paidSeats` < `seats` (только в блоке состава). Запись, разделённая между составом и очередью, показывается в обоих блоках; в очереди после числа мест добавляется «(+N)» не нужно: просто своё число мест в очереди. Блок «⚠ Мест нет! В очереди:» выводится только если очередь не пуста.

## 11. Примеры очереди (для тестов)

Обозначения: вместимость C, запись `Имя:seats`, состав/очередь в местах.

| № | Было | Действие | Стало |
|---|---|---|---|
| 1 | C=4, пусто | A +3 | A: 3 в составе |
| 2 | C=4, A:3 | B +3 | A: 3; B: 1 в составе, 2 в очереди |
| 3 | C=4, A:3, B:3 (1+2) | A отменяет | B: 3 в составе (очередь пуста) |
| 4 | C=4, A:3, B:3 (1+2) | A уменьшает до 1 | A: 1; B: 3 в составе |
| 5 | C=4, A:2, B:2, D:1 (очередь) | B отменяет | A: 2; D: 1; свободно 1 |
| 6 | C=4, A:2, B:2, D:1 (очередь) | D увеличивает до 3 | D: 3, всё в очереди (мест нет) |
| 7 | C=3, A:1, B:1 (свободно 1) | A увеличивает до 5 | A: 3 в составе, 2 в очереди; B: 1 в очереди (B теряет место в составе: A раньше по порядку) |
| 8 | C=4, A:3, B:2 (1+1 очередь) | организатор C=2 | A: 2 в составе, 1 в очереди; B: 2 в очереди |
| 9 | C=4, A:3, B:2 (1+1) | организатор C=8 | A: 3; B: 2 в составе |
| 10 | C=4, A:1 | A: PUT seats=6 | ошибка `SEATS_LIMIT_EXCEEDED`, состояние не меняется |
| 11 | C=2, A:2, B:1 (очередь) | организатор удаляет A | B: 1 в составе |
| 12 | игра cancelled | любой PUT/DELETE signup | ошибка `GAME_NOT_ACTIVE` |
| 13 | C=4, A:2 | A: PUT seats=2 повторно | без изменений (идемпотентно) |
| 14 | C=4, A:3 оплачено 3 | A уменьшает до 2 | `paidSeats` = 2 |

Пример 7 — следствие п. 2 и 6: состав пересчитывается заново, порядок записей сохраняется. Допущение: это поведение допустимо, так как лимит 5 мест ограничивает вытеснение; организатор видит изменения в реальном времени.
