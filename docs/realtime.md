# Реалтайм: WebSocket `/ws`

## Подключение и авторизация

- URL: `wss://<host>/ws`. Клиент первым сообщением отправляет `{"type":"auth","launchParams":"<строка параметров запуска VK>"}`.
- Сервер проверяет подпись так же, как для REST. Успех: `{"type":"auth.ok"}`. Неудача: `{"type":"auth.error"}` и закрытие соединения с кодом 4401.
- До `auth.ok` остальные сообщения игнорируются; таймаут на авторизацию 10 секунд.

## Подписки (клиент → сервер)

| Сообщение | Смысл |
|---|---|
| `{"type":"subscribe","topic":"games"}` | общий список игр |
| `{"type":"subscribe","topic":"game","gameId":N}` | конкретная игра |
| `{"type":"unsubscribe","topic":"game","gameId":N}` | снять подписку |
| `{"type":"ping"}` | в ответ `{"type":"pong"}` |

## События (сервер → клиент)

Каждое событие несёт полное актуальное состояние, а не дифф, чтобы клиент не держал порядок применения.

| Событие | Когда | Тело |
|---|---|---|
| `game.created` | создана игра | `{"type":"game.created","game": GameSummary}` → подписчикам `games` |
| `game.updated` | игра изменена, отменена, изменился состав | `{"type":"game.updated","game": GameSummary}` → подписчикам `games` |
| `roster.updated` | изменилась запись, оплата, вместимость, команды, счёт матча, порядок встреч, лучший игрок | `{"type":"roster.updated","game": GameDetails}` → подписчикам `game:N` |

Схемы `GameSummary` и `GameDetails` — как в `openapi.yaml`. Поле `mySeats` в событиях не передаётся (зависит от получателя), клиент считает его по `roster` и `vkId`.

## Heartbeat и переподключение

- Сервер отправляет WebSocket ping каждые `WS_HEARTBEAT_SEC` секунд; соединение без pong в течение двух периодов закрывается.
- Клиент при разрыве переподключается с экспоненциальной задержкой (1, 2, 4, … максимум 15 секунд, с джиттером), заново авторизуется, заново подписывается и перезагружает состояние по REST (`GET /games`, `GET /games/:id`), чтобы не потерять события за время разрыва.
- Клиент также перезагружает состояние при возврате приложения в активное состояние (`VKWebAppViewRestore`).
- Запасной режим: если WebSocket недоступен 3 попытки подряд, клиент опрашивает REST каждые 5 секунд, пока не удастся подключиться.

## Порядок и гарантии

- Событие отправляется после успешного коммита транзакции.
- Доставка «не более одного раза» без гарантий порядка при разрыве; консистентность обеспечивается перезагрузкой по REST после переподключения.
