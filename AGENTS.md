# Правила для ИИ-агентов

Проект: VK Mini App «Запись на футбол». Сначала прочитайте `README.md` и `docs/spec.md`. Контракты (`docs/openapi.yaml`, `docs/realtime.md`) меняются только осознанно и вместе с кодом и тестами.

## Решения, которые не пересматриваются без владельца

- Одна платформа: VK Mini App. VK Tunnel отключён платформой, не использовать.
- Оплата ручная (организатор отмечает «оплачено»). Лимит: не более 5 мест на человека в одной игре (`MAX_SEATS_PER_USER` в `packages/shared`).
- Очередь FIFO; при нехватке мест запись делится между составом и очередью.
- SQLite (`node:sqlite`), один процесс API. Секреты (`VK_APP_SECRET`) только в переменных окружения на сервере, не в репозитории, логах и чатах.

## Структура и команды

`apps/api`, `apps/web`, `packages/shared`; команды из корня: `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, e2e: `pnpm --filter @football/web test:e2e`.

## Соглашения кода

- TypeScript strict, `erasableSyntaxOnly` (нет `enum`, `namespace` и параметров-свойств конструктора), `verbatimModuleSyntax` (типы через `import type`), `noUncheckedIndexedAccess`.
- Импорты локальных файлов с расширением `.ts`.
- Бизнес-логику очереди держим в `packages/shared` как чистые функции; сервер и клиент не дублируют её.
- Тексты интерфейса и сообщения об ошибках на русском; коды ошибок и поля API на английском.
- Коммиты: английский, повелительное наклонение, одна логическая правка на коммит.

## Проверка работы

Среда разработки может не иметь доступа к реестру npm. Тогда код проверяется через GitHub Actions: CI публикует итог каждого шага аннотацией (`ci/run.sh`), его можно прочитать через `gh api repos/<repo>/check-runs/<id>/annotations`. Не считайте задачу готовой, пока CI не зелёный и e2e не прошёл.

## Выкладка

См. `docs/runbook.md`. Скрипты на сервере по умолчанию только показывают план (`--apply` для выполнения). Чужие сервисы и конфиги nginx на сервере не трогаем.
